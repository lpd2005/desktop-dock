## 推荐顺序

建议顺序为：**配置与启动可靠性 → 性能和恢复验收 → 显示变化适配 → 文件夹展开 → 回收站状态**。优先保证已有体验，再按实测结果扩展功能。

### 第一轮：稳定性与性能验收（建议接下来的开发轮次）

| 优先级 / 编号 | 工作 | 当前进展与验收 |
| --- | --- | --- |
| P0 / R1 | 处理便携长路径下的自启设置错误 | preview.25 已复现并修复：仅禁用自启选项并解释原因；隔离注册表与真实设置页检查通过，普通路径的登记 / 移除检查继续通过 |
| P0 / R2 | 加强配置损坏与写入失败处理 | preview.25 已完成有效备份、确认恢复、损坏归档与保存重试；核心文件锁 / 只读 / 失败检查及真实 UI 集成通过。备份更新检查不代表硬件断电容灾已验证 |
| P0 / R3 | 补齐真实使用生命周期验收 | preview.26 已接入暂停 / 恢复，环境消息与实际任务栏恢复检查通过；真实登录自启、锁屏 / 解锁、休眠 / 唤醒及 Explorer 重启仍待实机验收，不能用模拟检查代替 |
| P1 / R4 | 建立当前版本性能基线 | 待长期和分组测量：当前只追加 smoke 短样本；仍需统一环境采集 CPU、工作集、专用内存、辅助进程及动画数据，检查重复操作后是否持续增长 |

R1、R2 已从代码审阅风险推进到失败复现与回归验证；原问题及修复位置如下：

- [StartupRegistration.cs](../src/DesktopDock.App/StartupRegistration.cs) 原先在构造时直接抛出超长命令错误；现保存不可用原因，由设置页限制自启操作，避免影响整个设置入口。
- [SettingsStore](../src/DesktopDock.Core/SettingsStore.cs) 从配置模型文件中分离，增加有效备份和显式恢复；[Controller.cs](../src/DesktopDock.App/Controller.cs) 负责保存失败提示和重试。其他缓存 / 恢复记录继续使用原有 [AtomicJson.cs](../src/DesktopDock.Core/AtomicJson.cs)，未改变任务栏恢复协议。

这一轮不增加新的常驻组件。每个修复先复现，再运行相应核心 / 原生回归；只修改相关实现，不借机改变现有视觉或点击规则。

### 第二轮：主屏与系统环境变化（建议后续预览版）

当前已存在显示变化处理，应在此基础上完善并验收，而非重新实现整套 Dock。

preview.26 已实现消息合并、关键变化时撤回旧输入区域、取消过期拖拽 / 预览及组件统一重定位，并覆盖了原生消息回归。以下真实显示组合与硬件步骤仍需完成，不能据此将第二轮整体标记为已验收。

- 验证 100%、125%、150%、200% 缩放与分辨率切换，图标、输入区域、底边触发和预览位置始终一致。
- 验证外接屏接入 / 拔出、主显示器切换，Dock、桌面面板和组件落在有效工作区，不留看不见的鼠标拦截区域。
- 处理显示与系统事件的连续触发，合并重定位；重建需要失效的图标 / 缩略图资源，取消已经过期的拖拽和预览。
- Explorer、显示器或工作区变化时，任务栏增强按当前保护规则停止并说明状态；保留恢复能力，不强行覆盖其他程序的工作区设置。

先完成“主屏变化后仍可正常使用”，再考虑选择目标显示器或每屏独立 Dock。后两项尚未实现，不与本轮合并承诺。

技术依据：[显示变化消息](https://learn.microsoft.com/en-us/windows/win32/gdi/wm-displaychange)、[DPI 变化消息](https://learn.microsoft.com/en-us/windows/win32/hidpi/wm-dpichanged)、[电源状态通知](https://learn.microsoft.com/en-us/windows/win32/power/wm-powerbroadcast)。这些接口说明是实现参考，不是兼容测试结果。

### 第三轮：日用功能扩展（候选 v0.2.0）

| 顺序 | 功能 | 最小范围与验收 |
| --- | --- | --- |
| 1 | 文件夹内容展开 | 先通过右键“展开文件夹”展示一级内容，保留原有打开入口；按需异步读取、限制一次显示数量、支持滚动 / 分页，关闭后释放资源；路径失效或无权限时显示明确状态，不自动递归扫描 |
| 2 | 回收站空 / 满状态 | 保留现有打开入口，增加状态图标与按需更新；优先使用 Shell 变化通知，避免高频全量扫描；若增加清空操作，必须经过明确确认，不影响 Dock 原有拖远移除的含义 |
| 3 | 配置导入 / 导出 | 在 R2 完成后考虑；导入先校验和预览，保留回退备份，不直接替换正在使用的有效配置；包含用户路径的导出文件只由用户自行保管，不进入仓库 |

每次只加入一项，记录关闭 / 开启时的资源差异。减少动画与关闭已有组件继续作为基础选项，不先添加缺乏测量依据的“性能模式”。

## 性能验证口径

当前 README 中约 70 MB 的描述是用户使用环境的观察值；历史验证记录还包含其他版本、开关和短样本，不能直接比较或作为统一性能承诺。

下一轮至少覆盖 10 / 20 / 40 个图标，分别测量 Dock 基础模式、时间 / 天气组件开启、窗口预览开启、顶部任务栏玻璃开启的场景。预热后采集不少于 10 分钟，单独进行至少 2 小时的日用稳定性观察，并反复打开设置、预览、拖拽和取消操作。

记录 Windows 构建、CPU / GPU 型号、分辨率、缩放、刷新率、开关、采样工具与时长；公开材料去除机器名称、用户路径、应用列表和窗口标题。辅助玻璃 / 恢复进程与 DWM 成本分别记录，不把 Dock 单进程占用当成总开销。

沿用 [PLAN.md](PLAN.md) 的初步目标：约 20 图标、60 Hz 下稳定呈现，基础模式空闲 CPU 平均低于 1%、工作集争取不超过 150 MB。它们仍是待验证目标。应用更新间隔不是 GPU 呈现帧率；高刷新率和功耗需要单独验证。

## 稳定版前的条件

- 当前核心功能、恢复、安装、升级、卸载和真实登录启动都有可复查的验收记录。
- 完成上述性能与长期运行检查，公开说明仍未覆盖的系统 / 硬件组合。
- 配置兼容与备份恢复经过检查；发布包不含个人数据、日志或凭据。
- 项目所有者确定源码许可证；有合适证书时再安排代码签名，未签名时继续明确说明。
- 先更新版本和说明，再按 [PUBLISHING.md](PUBLISHING.md) 构建、验证和发布；纯文档调整不新建应用版本或标签。

## 保留的范围限制

不在上述排期中加入动态壁纸引擎、新建顶部菜单栏、系统窗口动画改造或后台自动安装服务。完整多屏另行规划。

继续保留透明无底板、原图标轮廓、白色运行短线 / 蓝色活动长线、底边停留唤出和原生任务栏式切换；不恢复已取消的启动弹跳、全局召回快捷键、外部窗口位置调整和应用进程强制退出。
