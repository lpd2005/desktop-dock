# Dock 交互与当前实现

当前以 0.1.0-preview.4 为准。preview.2 的启动动效和窗口位置调整已按用户要求移除。

## 显示、遮挡与召回

使用可见、未最小化且未被系统隐藏的应用窗口边界，检查是否与 Dock 的静止底座区域重叠。普通窗口也能触发隐藏；不要求窗口最大化。桌面、原生任务栏、自身菜单与提示不作为应用遮挡。主显示器以外的窗口不相交时不影响 Dock。

窗口事件触发遮挡状态更新，低频计时器处理召回超时和状态回退。Dock 隐藏时停止动画，不占用整条屏幕底边；没有遮挡时仍保留可选的普通自动隐藏。

默认 Ctrl+Alt+Shift+D 召回。通过 RegisterHotKey 与 MOD_NOREPEAT 注册，不使用键盘注入或低级键盘钩子。注册失败时尝试相同修饰键加 J、K、U，设置和托盘展示实际成功的组合；全部失败时托盘仍可召回。避免使用 Windows 键和 F12 等保留组合，但不能保证第三方程序自行定义的局部快捷键没有重复。

遮挡期间召回后，3 秒未操作 Dock 则隐藏。实际鼠标移动、点击、滚轮消息和 Dock 菜单操作重置计时；鼠标静止不刷新计时，其他应用中的输入也不刷新。窗口遮挡消失后，等待约 250 ms 稳定状态再显示。

依据：[RegisterHotKey](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerhotkey)。

## 应用图标的任务栏语义

- 没有可匹配窗口：正常启动。
- 目标窗口当前活动且没有最小化：再次点击最小化。
- 目标窗口已最小化：恢复。
- 目标窗口在后台：激活。
- 右键菜单的打开操作只打开 / 激活，不最小化。

EXE、快捷方式目标、应用 URI、应用标识和本次启动窗口用于关联图标。链接只读取目标信息，不修改原快捷方式；窗口关联只保存在当前进程内。文件夹、URL 和带参数的入口优先使用本次启动后关联的窗口，避免泛化到无关窗口。

多窗口应用当前处理活动或最近关联的窗口；完整缩略图选择仍属后续范围。自定义启动代理、权限受限程序和特殊窗口需要继续兼容验证。无法可靠识别时保留正常启动，不猜测操作其他应用。

通过 ShowWindowAsync 最小化 / 恢复，保留应用内容；应用启动和切换不关闭或移动外部窗口。只有用户主动开启的任务栏增强管理原生任务栏及其顶部预留工作区。

依据：[ShowWindowAsync](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-showwindowasync)、[AppUserModel.ID](https://learn.microsoft.com/en-us/windows/win32/properties/props-system-appusermodel-id)。

## Alt+Tab 闪现修复

旧预览为了便于截图曾使用 WS_EX_APPWINDOW，导致 Dock 进入任务切换列表；切换中又可能短暂判定应当显示。

当前正式运行与安全预览均固定使用 WS_EX_TOOLWINDOW、WS_EX_NOACTIVATE，不设置 WS_EX_APPWINDOW。设置也是工具窗口，不进入任务栏或 Alt+Tab。切换期间抑制显示，并等待稳定状态再显示，避免前台中间状态造成闪现。

自动回归检查窗口样式和切换状态序列；不向用户其他应用注入 Alt+Tab。真实切换器的全部视觉路径仍需要继续验收。

依据：[Extended Window Styles](https://learn.microsoft.com/en-us/windows/win32/winmsg/extended-window-styles)。

## 保留的视觉与性能策略

保留原有浅 / 深色玻璃、细描边、阴影、分组线和连续悬停放大。图形、命中判断和系统窗口区域使用相同几何数据，空白区域不阻挡其他应用。动画只在悬停变化时更新，稳定后停止；不修改系统全局计时器分辨率。

已经移除启动弹跳、设置淡入 / 位移动效、外部窗口尺寸和位置调整，相关设置与代码也删除。不会持续捕获外部窗口，也没有灯神展开的截图合成层。应用识别只在启动后短时跟踪，识别后停止，最长 5 秒。

更新间隔指标代表应用提交节奏，不等于 GPU 实际呈现帧率；不能仅凭低 CPU 占用声称达到 macOS 的流畅度。

## 顶部原生任务栏增强

默认关闭，仅在用户已将主屏原生任务栏置顶时启用。不改位置、注册表或系统自动隐藏偏好，不注入鼠标 / 键盘输入。120 ms 低频检查鼠标位置与交互状态；顶边停留 180 ms 显示、离开 750 ms 隐藏，Alt+Tab 期间抑制边缘触发。原生开始、搜索与托盘菜单操作时保持显示。检测只读鼠标位置，没有顶部输入窗口。

控制原生任务栏窗口的可见性。如果系统已经启用原生自动隐藏，则让 Windows 自己处理显示。只释放确认属于该顶部任务栏的预留区域，临时调用 SPI_SETWORKAREA，不写入系统偏好。Explorer 或玻璃组件初始化可能重新预留原来的条带，因此以一秒回退检查协调；只认本次记录的原始区域与展开区域，其他工作区更改会使增强停止。不会移动、重新最大化用户已经打开的窗口。

变更前原子写入恢复记录，并启动一个等待父进程退出的独立恢复进程。记录包含当前任务栏窗口、进程启动时间和原工作区，仅在本机保存。正常关闭恢复后通知守护进程退出；异常结束则由它恢复。资源管理器、任务栏位置或显示器改变时恢复并暂停，避免将旧几何应用到新环境。

玻璃使用未修改的 TranslucentTB 2026.2 官方便携程序，独立运行，不将其代码链接入 Dock。固定下载 SHA-256，分发原许可证、同版本源码及来源说明，运行前验证组件文件哈希。运行副本和配置位于本机应用数据目录。检测到已有实例时不修改其配置或停止它；只清理本软件数据目录中由本软件管理的副本。

该组件会通过自己的 Explorer XAML 集成设置背景，并负责外观恢复。关闭玻璃、关闭增强或退出时停止受管理副本；守护进程也覆盖父进程在启动副本后尚未完成 PID 记录就退出的短暂间隙。任务视图和节电状态交还系统外观。系统更新可能改变兼容性，因此 UI 展示组件状态，允许分别停用隐藏与玻璃。

参考：[TranslucentTB 源码与许可证](https://github.com/TranslucentTB/TranslucentTB)、[SystemParametersInfo](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-systemparametersinfow)。
