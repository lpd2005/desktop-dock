# 性能采样与优化

本页说明 preview.28 的可复查采样方式。数据来自带采样入口的开发构建，不能把短样本、应用更新节奏或单进程数据当成整机功耗、GPU 呈现帧率或统一硬件承诺。

## 已做的优化

- 应用身份快照的缓存命中路径不再创建捕获参数的闭包，仍在每轮窗口扫描时重新建立快照，避免 PID / 窗口身份变化后的旧值长期残留。
- 设置窗口的预览和固定入口复用 Dock 已解码的图标及冻结位图，图片缓存最多 64 项。关闭再打开设置无需对同一批图标重复执行 Shell 图标提取和像素归一化；布局和点击行为保持原样。

专项缓存命中微基准在预热后读取同一进程名称一百万次：修改前累计分配 88,000,000 字节，修改后为 0。此数字只描述该缓存命中路径，不代表整个应用零分配。发行回归同时检查名称 / 路径 / 应用标识命中无闭包分配、同一快照共享读取，以及新快照刷新不可用标识。

## 采样方法

正常退出日用 Dock 后，在仓库根目录通过 PowerShell 7 运行：

```powershell
./scripts/Measure-Performance.ps1 -Executable ./DesktopDock.exe -IconCounts 10,20,40 -Profiles base -Seconds 600 -WarmupSeconds 30 -Label baseline
```

将 Executable 改为本机完整运行包中的 DesktopDock.exe。脚本会创建忽略的独立输出目录，不复制日用配置；每个场景使用新进程，默认预热 30 秒、采样 10 分钟，每秒读取主进程数据。固定入口为示例快捷方式，交替指向八种可执行文件身份；固定应用数之外另有桌面面板与设置两个内置入口。Dock 保持显示，保留正常的遮挡与应用状态扫描，鼠标输入被隔离，不主动操作个人应用。

| 场景 | 内容 | 边界 |
| --- | --- | --- |
| base | Dock、原图标、倒影和状态扫描 | 组件、任务栏增强关闭，无未处理消息提醒 |
| widgets | 时间与天气组件 | 预览天气不联网，不能代表真实网络更新成本 |
| previews | 两个示例窗口与实时缩略图 | 示例窗口仅用于构造负载，不统计为 Dock 辅助进程 |
| glass | 主屏顶部任务栏隐藏、玻璃及恢复守护 | 需要任务栏已经在顶部；退出恢复原状，不自动搬移 |

可传入 `-Profiles base,widgets,previews,glass` 依次测量。`-Seconds 2 -WarmupSeconds 0` 只用于检查脚本与场景是否可运行；结果会标记 ShortSample，不能用作稳定性能结论。

脚本记录 CPU / 显卡型号及驱动报告的分辨率、刷新率；主报告补充 Windows 构建、缩放、主屏尺寸与是否使用硬件渲染。记录不包含机器名称、账户路径、个人应用列表或窗口标题。生成的示例配置和快捷方式仍含本机路径，整个输出目录只在本机保管，不随源码、问题反馈或发布包上传。

## 指标口径

- CPU 用进程 CPU 时间增量除以墙钟时间和逻辑处理器数量，数值为所有逻辑处理器归一化后的百分比。
- WorkingSetMiB 为总工作集，PrivateMiB 为私有提交量，和任务管理器不同列的数字不能直接混用。分配率包含采样代码自身的托管分配；前后比较使用同一主进程采样器。
- 外部脚本约每 5 秒单独读取同一会话的 DWM，以及本次创建的玻璃 / 守护进程。无法读取时标记 UnavailableRoles，不填造零值。DWM 数据包含其他桌面活动，不能全部归因于 Dock。
- 空闲采样完成后执行六次悬停波形和十次设置打开 / 关闭，记录应用动画更新间隔及私有提交量差值。该间隔不等于 GPU 呈现帧率；设置循环的一次内存差值也不能证明长期泄漏或回收效果。

## 当前测量与限制

本轮环境：Windows 11 x64、系统构建 26300，Intel Core i9-14900HX、NVIDIA GeForce RTX 4060 Laptop GPU，主屏 2560 × 1600、150% 缩放，驱动报告 240 Hz；使用硬件渲染。高刷新率只是环境信息，本轮没有测量 GPU 实际呈现帧率或功耗。开发桌面的其他活动未被完全隔离。

20 个固定入口的前后样本均预热 30 秒、采样至少 600 秒，固定入口加两个内置入口共 22 个图标。

| 指标 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 空闲平均 CPU | 0.0288% | 0.0269% |
| 平均总工作集 | 167.5 MiB | 169.4 MiB |
| 平均私有提交量 | 118.2 MiB | 119.2 MiB |
| 托管分配率（含采样器） | 37.7 KiB/s | 32.3 KiB/s |
| 空闲高频动画更新数 | 0 | 0 |
| 十次设置循环后的私有提交量差值 | +55.4 MiB | +50.9 MiB |

本组分配率降低约 14%，缓存微基准和图片复用检查提供了对应实现证据。CPU 差异很小，桌面上的其他活动未被完全隔离，不能据此宣称普遍加速。总工作集没有降低，仍高于路线中 150 MiB 的初步目标；设置循环差值受首次加载、缓存与垃圾回收时机影响，继续需要长期观察。

修改后的基础场景还完成了不同入口数量的独立采样；每组预热 30 秒、采样至少 600 秒，均保留倒影、关闭组件与任务栏增强，无未处理提醒。

| 10 / 12 | 0.0233% | 163.0 MiB | 109.6 MiB | 28.0 KiB/s | 0 |
| 20 / 22 | 0.0269% | 169.4 MiB | 119.2 MiB | 32.3 KiB/s | 0 |
| 40 / 42 | 0.0302% | 174.1 MiB | 126.2 MiB | 41.6 KiB/s | 0 |

基础场景没有启动玻璃 / 恢复辅助进程。外部脚本取得每组 119 个 DWM 样本，总工作集均值约 150.4–150.7 MiB；这是整个桌面合成进程的上下文，不能计为 Dock 独占成本。此次 DWM CPU 计数没有可分辨的增量，不能解释为零开销。基础 / 组件 / 预览 / 玻璃四个场景的短运行均已完成，只验证采样入口可运行。

组件 / 预览 / 玻璃的完整长样本与至少两小时日用观察按 [开发路线](ROADMAP.md) 继续登记；未完成项不标记为验收通过。原始报告、硬件上下文和截图均保存在忽略的本地产物目录。
